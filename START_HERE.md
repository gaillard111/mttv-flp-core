# You arrived from a gist — read this first

You have one small Python file. It shows a single, specific defect and its fix, and it stops
with an error if the defect comes back. That is all it claims.

- **Run it** — `python graines/<the-file-you-got>.py`. No dependency, no network, no account.
- **What it is** — six short programs, each born from an error actually made and measured. Each
  contains the faulty version, the corrected one, and the assertions that tell them apart.
- **Start with the catalogue** — [`graines/README.md`](graines/README.md), one line per seed.
- **Then the reasoning, if you want it** — [`SYNTHESE_MTTV_FLP.md`](SYNTHESE_MTTV_FLP.md).
- **What you may ignore** — everything under `expansion_v2026.5/`, `docs/` and `protocols/`.
  That is a doctrinal corpus with its own vocabulary. It is not needed to read the code, and it
  is not what the gist was about.

The project is called MTTV-FLP. Its claim is modest and unpopular: a system is not made robust
by being optimised, but by keeping a margin it never spends. The six programs test six precise
consequences of that claim. **None of them proves it.**
